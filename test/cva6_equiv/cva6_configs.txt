# chipsalliance/sv-tests defines (its generators/ariane `lists`).  sv-tests
# builds the full core at five configurations and scores whether the tool reads
# it; this adds our own structural gate on top -- every net the source assigns
# must have a driver.
#
# Format:  <config-package-basename>  <expected-undriven-nets>  <note>
#
# `expected-undriven-nets` is the number of DISTINCT nets `check` may report
# after proc/flatten/opt_clean.  It is a RATCHET: a config that reports fewer
# is an unexpected success and must be updated here in the same commit that
# improves it.  Each non-zero expectation names the net and why below.
#

# per-instance chip sweep already cover in depth; it is listed so a regression
# in the whole-core read is caught here too.
