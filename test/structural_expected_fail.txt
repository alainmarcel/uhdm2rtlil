# Tests whose `test_structural.ys` is EXPECTED to fail: the reader defect it
# asserts against is known and tracked, and the check is kept so the shape is
# measured every run rather than re-derived when someone returns to it.
#
# This is a RATCHET, exactly like failing_tests.txt and
# slang_miter_expected_fail.txt: a listed check that starts PASSING is reported
# as an UNEXPECTED SUCCESS, so the entry must be removed in the same commit
# that fixes the defect.
#
# Use this list ONLY for a structural check.  A test whose whole run fails
# belongs in failing_tests.txt; a read_uhdm-vs-read_slang miter counterexample
# belongs in slang_miter_expected_fail.txt.

# ---- sv-tests conversion campaign, 2026-10-31 ------------------------------
# Seven conversions whose `test_structural.ys` proves upstream's own asserted
# values and FAILS on read_uhdm today.  Each was measured against a reference
# before being listed; the netlists are pure wiring (0 gates), so the ordinary
# uhdm-vs-verilog gate-count comparison is VACUOUS on them and the structural
# proof is the only real check -- which is exactly why these would otherwise go
# unnoticed.


# A whole-array assignment between REVERSED ranges (`int A[3:0]` -> `int B[0:3]`)
# must copy by POSITION, so B[0] takes A[3].  read_verilog and read_slang do;
# read_uhdm copies by INDEX (b0 = 0 where the golden gives 3).  Upstream's own
# $display asserted this exact ordering.
sv_tests/array-unpacked-assignments

# `c >>>= 3` on a `logic signed [7:0]` loses its SIGNEDNESS: at -120 read_verilog
# gives 8'hf1 (-15) and read_uhdm 8'h11 (a logical shift of 0x88).  The
# NON-compound form `c = a >>> 3` is correct in the same test file, so the gap is
# in the compound assignment operator alone.
sv_tests/arith_shift_assignment_signed

# A REPLICATION inside an unpacked-array assignment pattern is dropped: every
# element it should fill reads 32'x.  `'{'{0,1,2},'{3{4}}}` fills row 1 correctly
# and leaves row 2 entirely X; `'{2{'{3{4, 5}}}}` leaves all of both rows X.
# read_slang fills both.  read_verilog cannot parse the pattern at all, so the
# slang miter and this proof are the only gates.
sv_tests/arrays
sv_tests/arrays-replication

# An INDEX-KEYED assignment pattern (`'{1:1, default:0}`) is dropped entirely:
# all three elements read 32'x where read_slang gives 1, 0, 0.
sv_tests/arrays-key-index

# A RANGED enum member list (`enum {start=10, step[10]}`) does not create the
# generated member names: read_uhdm reports `Reference to unknown signal: step0`
# and fabricates a wire, where read_slang resolves step0..step9 to 11..20.
sv_tests/enum_sequence

# $countones / $countbits are not implemented: the reader warns
# `Unhandled system function call` and returns the ARGUMENT, so all five counts
# read 1879082017 at 32'h70008421 instead of 7 / 25 / 32 / 0.  read_verilog is
# the oracle; read_slang refuses the functions outright so there is no miter.
sv_tests/countbits_function

# ---- sv-tests conversion campaign, batch 3b (2026-10-31) -------------------

# A COMPOUND ASSIGNMENT USED AS AN EXPRESSION evaluates to the RHS alone: at
# x = 7, `b = (a += 1)` gives read_verilog a=8/b=8 and read_uhdm a=1/b=1 -- the
# `a +` part is lost.  `b = (a -= 1)` likewise gives 1 instead of 6.  The
# PRE-INCREMENT form `b = (++a)` and a plain chain `a = (b = (c = x))` are both
# correct in the same shape, so the gap is the compound operators.  Related to
# the `>>>=` signedness loss recorded for arith_shift_assignment_signed above.
sv_tests/assign_in_exp
sv_tests/assign_in_exp_sim
sv_tests/assignment_in_expression
sv_tests/assignment_in_expression_sim

# A SELECT APPLIED TO A CONCATENATION takes the wrong bits: `{b,c}[9:6]` with
# b = 8'b10101100 and c = 8'b01010011 is 4'b0001 (b[1:0] then c[7:6]), which
# read_slang gives; read_uhdm gives 4'b0011.  read_verilog cannot parse the form
# at all (`syntax error, unexpected '['`), so read_slang is the oracle.
sv_tests/concat_op-bit_select

# `foreach` IS NOT UNROLLED in a combinational context: read_uhdm warns
# `Cannot unroll foreach in comb context` and emits nothing, so the loop's work
# is lost (foreach_loop reads 0 visits and sum 0 where read_slang gives 4 and
# 1110; foreach_loop_synth leaves the copied elements undriven).  read_verilog
# cannot parse `foreach`, so read_slang is the oracle.
sv_tests/foreach_loop
sv_tests/foreach_loop_synth

sv_tests/atan2_function

sv_tests/ln_function

# ---- sv-tests conversion campaign, batch 4 (2026-10-31) -------------------

# An `initial assume` is DROPPED: read_uhdm lowers an immediate `assert` and an
# immediate `cover` to a $check cell but emits nothing for an immediate `assume`,
# where read_verilog emits one.  (The deferred `#0`, `final` and concurrent
# `assume property` forms reach a netlist on NONE of the three frontends, so
# those tests do not assert a cell at all -- see each NOTE.md.)
sv_tests/assume_test

# A BARE `return` in a VOID FUNCTION does not skip the rest of the body: `fun`
# writes 1, returns early at a == 21 and otherwise writes 2, and read_uhdm
# reaches the second write EITHER WAY (read_slang gives 1 and 2).  The value form
# `return <expression>` is correct (jump_return_expr), and so is returning the
# function's own name, so the gap is the bare `return` as a control transfer.
# read_verilog cannot read the construct (`Can't resolve task name \return`).
sv_tests/jump_return

# ---- sv-tests conversion campaign, batch 5 (2026-10-31) -------------------

# A RANGED enum member list with explicit bounds (`enum {start=10, stop[11:13]}`)
# does not create stop11/stop12/stop13: read_uhdm reports
# `Reference to unknown signal: stop11` and fabricates a wire, where read_slang
# resolves them to 11, 12 and 13.  read_verilog cannot parse a ranged enum.  Same

sv_tests/enum_sequence_range

# `always @(edge clk)` becomes a COMBINATIONAL LOGIC LOOP: read_uhdm emits a plain
# $not driving `a` from `a`, so `check` reports four logic loops (one per bit).
# No frontend synthesizes a dual-edge flop -- read_verilog cannot parse the form
# and read_slang REFUSES it ("@(edge) will not be synthesized") -- but read_uhdm
# is the only one that silently produces a broken netlist instead of refusing.
sv_tests/event_control_edge


# A `let`'s FORMAL ARGUMENTS are not bound: read_uhdm reports
# `Reference to unknown signal: x` (and y, z) for `let op(x, y, z) = |((x|y)&z);`
# and the expression reads fabricated wires, so the output is 1'x where read_slang
# gives 1.  read_verilog cannot parse `let` at all
# (`syntax error, unexpected '='`), so read_slang is the oracle.
sv_tests/let_construct


# ---- sv-tests conversion campaign, batch 8 (2026-11-01) -------------------

# `repeat` IS NOT UNROLLED in a combinational context.  With a CONSTANT count
# (`repeat(128)`) read_verilog unrolls it and the accumulator reads 128; read_uhdm
# warns `Unsupported statement type in comb context` and leaves it at 0.  Same
# family as the `foreach` gap in foreach_loop above.  read_slang refuses `repeat`
# outright, so read_verilog is the oracle and there is no miter.
sv_tests/repeat_loop

# A `real` is measured as 32 BITS, not 64.  `$bits(T)` with `T` a type parameter
# defaulting to `real` gives read_slang 64 and read_uhdm 32; `$bits(real)` written
# directly gives read_slang 64 and read_uhdm 0, with `Empty argument in
# sys_func_call $bits` -- the type keyword is not accepted as an argument at all.
# read_verilog cannot parse a `type` parameter, so read_slang is the oracle.
sv_tests/parameter_type

# An INDEXED PART-SELECT of an UNPACKED array loses the array: read_uhdm warns
# `Base signal 'arr_a' not found in module or generate scope` for both operands of
# `arr_b[4+:c] = arr_a[1+:c]` and the destination reads all-zeros, where read_slang
# performs the copy.  read_verilog rejects the form (`Invalid array access`).  The
# PACKED counterpart is correct -- operations-on-packed-arrays-variable-slice-rw
# passes -- so the gap is the unpacked case.
sv_tests/operations-on-unpacked-arrays-variable-slice-rw
