# ---- incomplete always_comb: read_slang is the outlier (2026-11-03) --------
# Both decoders have an `always_comb` that assigns some of its targets up front
# and leaves others (`macro_instr_type`, `instr_o_reg`, `xreg1`, `xreg2`,
# `offset_reg`; zcmt_decoder's `instr_o`) written only inside
# `if (is_macro_instr_i)` and its nested `unique case`es.  SystemVerilog gives
# such a variable storage on an unassigned path, so yosys's proc_dlatch infers
# a latch -- for read_uhdm AND for read_verilog, the golden frontend.
# read_slang instead treats those paths as don't-care and emits pure
# combinational logic: each module's miter log has every "Latch inferred"
# warning BEFORE the `read_slang` line and none after it (22 for macro_decoder,
# 5 for zcmt_decoder).  A latch holds where slang's logic is a function of the
# inputs alone, so the miter differs on a path the design never takes, which is
# why the Verilator co-sim passes on both sides.  read_uhdm agrees with
# read_verilog; the reference is the odd one out.  Applies to every CVA6
# flavour the sweep builds (default, HPDcache, H-extension, RV32).
macro_decoder
zcmt_decoder

# Same class, openc910 and opene906 (2 rows): pmu's state machines are
# `always @(cur_state ...)` blocks whose `case (cur_state)` has NO default arm
# and NO pre-case assignment (pmu.v:378-455 for `next_state`, likewise
# `pg_next_state`, `x_tap2_sm.tap2_nxt_st`, and the incomplete APB read decode
# at pmu.v:216 for `pmu_apb_prdata[3:0]`), so an unlisted state leaves them
# unassigned and a latch is the faithful lowering.  3 "Latch inferred" warnings
# in the FIRST PROC_DLATCH pass of its miter log (read_uhdm) and 0 in the
# second (read_slang).  Co-sim passes on both sides.
pmu

# ---- out-of-range array READ, X by the LRM (2026-11-05) ---------------------
# OpenPiton's TLBs declare `reg [TLB_CSM] tte_csm_buf [1:0]` and index it with
# the 2-bit `wr_tte_csm_thrid`; the cex (bw_r_dtlb, -show-inputs: thrid=3,
# wr_csm_sel=0, wr_vld=1 at steps 1-2) takes the `tte_csm_ram[j] <=
# tte_csm_buf[wr_tte_csm_thrid]` arm with thrid 3, a READ past the end of the
# array.  LRM 7.4.6 makes that read X.  read_uhdm sizes the port address to
# the memory (ABITS 1) and reads entry 1 -- exactly what Verilator does, which
# is why the co-sim PASSES on both rows -- while read_slang keeps the 2-bit
# address (ABITS 2) and yosys's memory model leaves an out-of-range read
# unconstrained, so the SAT miter can always pick a different value.  No
# netlist is wrong on a defined input; the difference exists only where the
# source reads X.  (The sister out-of-range WRITE is ignored by both the LRM
# and read_uhdm since #1446.)  Co-sims: both `✅ PASS (301 cycles)` after the
# always_ff blocking-temp fix.
openpiton/bw_r_dtlb
openpiton/bw_r_itlb
