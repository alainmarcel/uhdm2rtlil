# This list covers the ones that had no hook at all: sweep_cva6 and the ext_ip

# This is a RATCHET: the sweep's summary names any listed row that now PROVES,
# so a stale entry is reported rather than hiding a fix.  An entry here does
# NOT excuse a co-sim divergence -- those are tracked separately and a row with

# ---- incomplete always_comb: read_slang is the outlier (2026-11-03) --------
# Both decoders have an `always_comb` that assigns some of its targets up front
# and leaves others (`macro_instr_type`, `instr_o_reg`, `xreg1`, `xreg2`,
# `offset_reg`; zcmt_decoder's `instr_o`) written only inside
# `if (is_macro_instr_i)` and its nested `unique case`es.  SystemVerilog gives
# such a variable storage on an unassigned path, so yosys's proc_dlatch infers
# a latch -- for read_uhdm AND for read_verilog, the golden frontend.
# read_slang instead treats those paths as don't-care and emits pure
# combinational logic: each module's miter log has every "Latch inferred"
# warning BEFORE the `read_slang` line and none after it (22 for macro_decoder,
# 5 for zcmt_decoder).  A latch holds where slang's logic is a function of the
# inputs alone, so the miter differs on a path the design never takes, which is
# why the Verilator co-sim passes on both sides.  read_uhdm agrees with
# read_verilog; the reference is the odd one out.  Applies to every CVA6
# flavour the sweep builds (default, HPDcache, H-extension, RV32).
macro_decoder
zcmt_decoder

# Same class, openc910 and opene906 (2 rows): pmu's state machines are
# `always @(cur_state ...)` blocks whose `case (cur_state)` has NO default arm
# and NO pre-case assignment (pmu.v:378-455 for `next_state`, likewise
# `pg_next_state`, `x_tap2_sm.tap2_nxt_st`, and the incomplete APB read decode
# at pmu.v:216 for `pmu_apb_prdata[3:0]`), so an unlisted state leaves them
# unassigned and a latch is the faithful lowering.  3 "Latch inferred" warnings
# in the FIRST PROC_DLATCH pass of its miter log (read_uhdm) and 0 in the
# second (read_slang).  Co-sim passes on both sides.
pmu

# ---- out-of-range array READ, X by the LRM (2026-11-05) ---------------------
# OpenPiton's TLBs declare `reg [TLB_CSM] tte_csm_buf [1:0]` and index it with
# the 2-bit `wr_tte_csm_thrid`; the cex (bw_r_dtlb, -show-inputs: thrid=3,
# wr_csm_sel=0, wr_vld=1 at steps 1-2) takes the `tte_csm_ram[j] <=
# tte_csm_buf[wr_tte_csm_thrid]` arm with thrid 3, a READ past the end of the
# array.  LRM 7.4.6 makes that read X.  read_uhdm sizes the port address to
# the memory (ABITS 1) and reads entry 1 -- exactly what Verilator does, which
# is why the co-sim PASSES on both rows -- while read_slang keeps the 2-bit
# address (ABITS 2) and yosys's memory model leaves an out-of-range read
# unconstrained, so the SAT miter can always pick a different value.  No
# netlist is wrong on a defined input; the difference exists only where the
# source reads X.  (The sister out-of-range WRITE is ignored by both the LRM
# and read_uhdm since #1446.)  Co-sims: both `✅ PASS (301 cycles)` after the
# always_ff blocking-temp fix.
openpiton/bw_r_dtlb
openpiton/bw_r_itlb

# ---- yosys memory_dff marks a reachable collision "don't care" (2026-11-06) --
# verilog-ethernet's axis_fifo loads its output pipeline register from the
# memory every cycle (`m_axis_pipe_reg[0] <= mem[rd_ptr_reg]`, unconditional
# on validity) and writes `mem[wr_ptr_reg] <= s_axis` in the same block, so
# an empty FIFO reads and writes the SAME word in one cycle.  Yosys 0.70's
# memory_dff merges our output FF into the read port and, for every
# same-clock write port, reports "don't care on collision" -- its
# QuickConeSat answers UNSAT to "can read and write collide", though a full
# `sat` on the same netlist finds the collision at once (rst=0, tvalid=1,
# rd_ptr == wr_ptr).  The merged port then returns X on the collision, the
# miter zeroes it and read_slang -- whose `m_axis_pipe_reg` is a $mem of its
# own, so nothing merges -- keeps the word.  Both rows PROVE with the
# ` memory_dff; opt_clean;` step removed from the miter recipe, and a
# directed `sat` on our netlist alone loads the register correctly without
# the merge.  (read_verilog on the same source asserts inside memory_dff,
# mem.cc:492 `port.en == State::S1`.)  axis_fifo_adapter instantiates
# axis_fifo; verilog-pcie vendors the same file.  Co-sim PASS on all four.
verilog-ethernet/axis_fifo
verilog-ethernet/axis_fifo_adapter
verilog-pcie/axis_fifo
verilog-pcie/axis_fifo_adapter

core-v-mcu/serial_deglitch

# ---- a struct member the source never assigns, read_slang leaves it FREE --
# cheshire's obi_demux drives every field of `mgr_ports_req_o[i]` in its
# `always_comb` except `rready`, which only `gen_rready` assigns and
# `ObiDefaultConfig` has `UseRReady: 0`.  read_uhdm latches the unassigned
# bit (it holds 0 from the all-zero init); read_slang lowers it to a
# `$bwmux` fed from the signal itself, which the SAT solver treats as an
# unconstrained bit -- `sat -prove dut.mgr_ports_req_o[0] 0` with every
# input defined FAILS on the read_slang netlist alone.  The counterexample
# differs on exactly bits 0 / 112 / 224 / 336 (the four `rready`s) and on
# nothing else.  Co-sim PASS (300 active cycles).
cheshire/obi_demux

# ---- a same-address write on both ports the source forbids (2026-11-06) ---
# prim_ram_2p's two write blocks are clocked by `clk_a_i` and `clk_b_i`,
# two DIFFERENT nets inside the model that prim_ram_2p_adv ties to one
# clock, and the model asserts `NoSameAddrWritePortA_A` /
# `NoSameAddrWritePortB_A`: a same-cycle write to one address from both
# ports never happens by contract.  The miter deletes the asserts and drives
# exactly that (a_addr == b_addr, both write, both masks partial); then
# which port's masked read-modify-write lands last is a write-port order the
# frontends number differently (read_uhdm port A, read_slang port B).  The
# source-order merge of #1440 cannot apply: at import the two clocks are
# distinct signals.  Co-sim PASS (185 active cycles).
opentitan-ip/prim_ram_2p_adv

# ---- `break` leaves later array elements unassigned, read_slang is the --
# ---- outlier (2026-11-06) ------------------------------------------------

# in a `for` that `break`s on the first taken prediction, and `phtWA[i]` /

# mispredict: element 1 of each is left unassigned on those paths, so its
# value holds -- a latch, which read_uhdm and read_verilog infer (5 "Latch
# inferred" warnings in the miter's first PROC_DLATCH pass, none in
# read_slang's).  The macro_decoder class.  The other signals in the
# counterexample (`phtWE`, `phtWA`, `port_i.brResult`) differ only in the
# ORDER the two frontends flatten an unpacked array into one vector
# (element 0 low on read_uhdm, high on read_slang), identically on both
# sides' outputs.  Co-sim PASS (53 active cycles).
rsd/Bimodal
