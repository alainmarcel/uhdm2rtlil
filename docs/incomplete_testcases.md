# Test cases no frontend can be judged on

Rows removed from [slang_unsupported.md](slang_unsupported.md) because the
harness could not give `read_slang` a fair run: a module no file of the test
defines, a test that is invalid on purpose, a design no frontend elaborates, a
co-simulation both netlists fail identically. Each row states which frontends
fail on it. Same recipes as the main report (R1 internal test, R2 yosys test, R3
external IP module, R4 core module).

What the harness already tries before a row lands here: for a yosys test, every
sibling test in the same directory that defines an instantiated module is added
as a `-v` library file (that is how the upstream `.ys` scripts read them), so an
"unknown module" row below is one no file of the yosys tests defines -- a vendor
primitive (`RAMB36E1`), a yosys internal cell, or a module the test deliberately
leaves out. For a sweep module, the family manifest's include dirs, defines and
configuration binds are applied; `elab-fail` means neither frontend elaborates the
module with them.
