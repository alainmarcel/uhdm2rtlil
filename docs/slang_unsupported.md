# What `read_slang` cannot read or gets wrong, across every test we run

`read_slang` (the vendored [sv-elab](https://github.com/povik/sv-elab) frontend built
into our Yosys) is the reference the regression proves `read_uhdm` against. This
report lists every place that reference is missing or wrong: the nightly IP and
core sweeps, the internal regression tests, and the upstream yosys tests, in one
format. Each row names a reason, links the test, and names the recipe that
reproduces it. Rows the harness could not give slang a fair run on are not here;
they are in [incomplete_testcases.md](incomplete_testcases.md) with a statement of
which frontends fail on them.

Generated by `test/slang_report.py` from `test/slang_coverage_sweep.sh`'s TSV and the
downloaded nightly sweep reports; regenerate after a regression + sweep cycle.

Inputs, with their vintages -- the two halves are NOT measured at the same time:
the **test** rows (internal + yosys) come from `slang_coverage.tsv` (2026-10-22), measured against the tree it
was run on; the **sweep** rows come from 47 downloaded report(s) under `build/sweeps/latest_1022` (2026-10-22), so they
are only as current as that download and do not reflect anything merged since.

## How to reproduce

All recipes run from a built tree (`make -j$(nproc)`), from `test/`.

| recipe | applies to | command | what you get |
|---|---|---|---|
| **R1** | an internal test `test/<name>` | `./slang_coverage_sweep.sh --one <name>` | prints the exact `read_slang` command the regression's source list gives (dut.sv or project.f, with its `-I`/`-D`), runs it, shows every diagnostic. A test with a `test_slang_equiv.ys` also has `yosys -m ../../build/uhdm2rtlil.so test_slang_equiv.ys` for the read_uhdm-vs-read_slang miter. |
| **R2** | an upstream yosys test `test/run/<path>` | `./slang_coverage_sweep.sh --one run/<path>` | same; the `run/` tree is what `run_all_tests.sh` generates from `third_party/yosys/tests` (run the regression once). Sibling tests defining an instantiated module are added as `-v` library files, as the upstream `.ys` scripts read them. |
| **R3** | an external IP sweep module (family has `test/ext_ip/<family>.json`) | `cd ext_ip && python3 ext_flow.py <family> <module>` | clone the manifest's repositories at their commits into `$EXT_IP_ROOT` (default `~/ext`, directory per `repos[].dir`) first. Prints the module's row: `formal vs slang` holds slang's diagnostic when it cannot read, `slang co-sim vs RTL` the Verilator verdict; the testbench and netlists stay in the family's work directory. |
| **R4** | a core sweep module (ibex, rp32, cva6, cva6-chip, pavona families, caliptra, opentitan) | `python3 core_sweep.py <core> --filter '^<module>$'` | sources are vendored under `test/`; same row format as R3. |
